GNU LAN NETWORK TESTING ENVIRONMENT · v8.0

Break the thing you own. Fix it faster.

An interactive terminal tool that puts real-world network condition — latency, jitter, loss, duplication, reordering, bandwidth — onto the devices you choose, so you can watch how they behave under pressure. It scans first. It asks permission first. It means both of those things.

▸ THE TOOL

One terminal, one screen, the whole neighbourhood — under test.

LAN SCAN

ARP-scans your network and fingerprints every device — vendor, hostname, open ports, type. Routers, phones, TVs, IoT; labels for all of it.

TARGET ANYTHING

One IP, several IPs, an entire subnet, or an IP resolved from a MAC. Whitelist your own devices before a range test and they are skipped automatically.

THE ENGINE

Traffic routed through your machine via ARP spoof, then shaped with tc netem — latency, jitter, loss, duplication, reordering, bandwidth. Applied on the wire, not in an app.

SANITY CHECKS

Every parameter is validated before it runs and its impact is estimated out loud. You cannot type nonsense into the void.

LIVE DASHBOARD

Every target is pinged once per second. Last, min, max, average, loss — rendered live while the test runs.

SELF-HEALING

Spoof processes are watched and restarted if they die. Targets are verified reachable first. Every long operation gets a loading bar.

▸ THE ENGINE

ARP spoof + tc netem. The polite version of turning someone's internet into a thinking exercise.

GNULTE reroutes a target's traffic through your machine and applies kernel-level shaping with tc netem. Every run ends in a full cleanup — qdisc removed, spoof processes killed, forwarding disabled — and a report with SVG latency graphs. It watches its own spoof process and revives it if it dies mid-test.

  • ▸ Latency — base delay with jitter (variance)
  • ▸ Loss / duplication / reordering — percentages you can dial in
  • ▸ Bandwidth limiting — chained under the netem qdisc (htb → netem), so nothing is lost
  • ▸ --random — parameters wander during the run, realistically
  • ▸ --capture FILE — tcpdump the target's traffic to a .pcap while testing
  • ▸ --dupcheck — detect duplicate IPs / ARP conflicts on your LAN

It refuses to lag the gateway or your own machine. It has standards.

▸ GNULTE-SCAN

The companion. GNULTE needs root — discovering your network does not.

gnulte-scan finds every active device and squeezes the maximum detail out of each one, with no root required when the arp-scan OUI database is present.

  • ▸ IP / MAC / OUI vendor / device type — routers, phones, TVs, printers, cameras, IoT, PCs
  • ▸ Device names from up to five sources: mDNS/Bonjour, reverse DNS, NetBIOS and more
  • ▸ Router detection by IP and MAC, so the gateway is always tagged — even when every OS is asleep
  • ▸ Optional --deep nmap pass: open ports + OS fingerprint
  • ▸ Export JSON / YAML / CSV
$ gnulte-scan --deep
[+] Gateway: 192.168.1.1 (Router) — OUI: NETGEAR
[+] 192.168.1.5 DESKTOP-NEPTUNE — OUI: Intel — ports 22,445 | OS: Linux
[+] 192.168.1.23 MiBox4 — OUI: Xiaomi — Android 9
[*] 8 devices, 2 routed through a switch someone forgot about
$ gnulte-scan -i wlan0 -C 192.168.0.0/24 -c > devices.csv

▸ COMMAND LINE

Flags in, trouble measured on the other side.

sudo GNULTE # interactive: scan → select → configure → run sudo GNULTE --quick # fast ARP-only scan sudo GNULTE --scan -t 192.168.1.20 # deep port/OS scan of one IP sudo GNULTE -t 192.168.1.20 --profile voip --duration 300 sudo GNULTE -r 192.168.1.0/24 -w 192.168.1.1 --profile throttle --duration 600 sudo GNULTE -t 192.168.1.20 --latency 1500 --jitter 800 --loss 5 --random --capture evid.pcap sudo GNULTE --dupcheck sudo GNULTE --stealth --verbosity expert --theme hacker

More flags live in GNULTE --help — targeting, shaping, export, logging, and the rest.

▸ THEMES & SETTINGS

A terminal tool that cares how it looks while it ruins your pings.

GNULTE --settings is an interactive app: pick a colour theme with a live preview, choose your verbosity — easy, normal, expert — and the console log mode. Changes save to ~/.gnulte.conf.

▸ RUN IT

Needs root and a few command-line companions.

# dependencies
sudo apt install arp-scan dsniff iproute2   # Debian / Ubuntu
sudo pacman -S arp-scan dsniff iproute2     # Arch / CachyOS

# install from this repo
sudo install -m755 GNULTE /usr/local/bin/GNULTE
sudo install -m755 gnulte-scan /usr/local/bin/gnulte-scan

sudo GNULTE

Packaged on Arch via the AUR PKGBUILD (packaging/aur), and installable from a .deb (packaging/deb) that ships /usr/bin/GNULTE, /usr/bin/gnulte-scan, a man page and docs.

▸ LEGAL

The part GNULTE reads at you before every single run.

GNULTE performs ARP spoofing to route traffic through your machine and kernel-level traffic shaping (tc). Using it against networks or devices you do not own, or without authorisation, is illegal in most jurisdictions. The in-app disclaimer must be accepted before any test runs — it is persisted in ~/.gnulte_accepted and GNULTE will keep asking until it is sure you meant it.

Use it on networks you own or have explicit written permission to test. You are solely responsible for your use. The wire remembers.
