GNULTE

Real network conditions, on the devices you choose.

GNULTE is an interactive terminal tool that puts real-world network problems — latency, jitter, packet loss, duplication, reordering and bandwidth limits — onto devices on your own network, so you can see how applications and hardware actually behave when the network is messing with them. It scans first, asks permission first, and cleans up after itself.

Features

A testing harness for the networks you actually own.

LAN scanning

ARP-scans your network and fingerprints every device — vendor, hostname, open ports and type. Routers, phones, TVs, IoT: all labelled.

Flexible targeting

One IP, several IPs, a whole subnet, or an IP resolved from a MAC. Whitelist devices before a range test and they are skipped automatically.

Traffic shaping

Traffic is routed through your machine via ARP spoof and shaped with tc netem: latency, jitter, loss, duplication, reordering, bandwidth — applied on the wire.

Sanity checked

Every parameter is validated before it runs and its impact is estimated out loud. You cannot type nonsense into the void.

Live dashboard

Every target is pinged once per second — last, min, max, average and loss rendered live while the test runs.

Self-healing

Spoof processes are watched and restarted if they die. Targets are verified reachable first, and long operations get a loading bar.

How it works

Four steps, a dashboard in the middle, and a report on the way out.

1

Accept the disclaimer

GNULTE is explicit about what it does. The disclaimer must be accepted before anything runs — and it keeps asking until it is sure you meant it.

2

Scan and select

It detects your interface, gateway and IP, then scans the network. Pick a target, several targets, or a whole subnet.

3

Shape the link

IP forwarding is enabled, arpspoof reroutes the target through your machine, and tc netem applies the conditions you chose. Bandwidth caps chain underneath the netem qdisc, so nothing is lost.

4

Watch and clean up

The dashboard pings every target each second. When it is over, everything is removed — qdisc, spoof processes, forwarding — and a report with SVG latency graphs is written.

gnulte-scan

The companion tool. GNULTE needs root — discovering your network does not.

  • IP, MAC, OUI vendor and device type — routers, phones, TVs, printers, cameras, IoT, PCs
  • Device names from up to five sources: mDNS/Bonjour, reverse DNS, NetBIOS and more
  • Router detection by IP and MAC, so the gateway is always tagged
  • Optional --deep nmap pass for open ports and OS fingerprinting
  • Export as JSON, YAML or CSV
# table view, no root needed $ gnulte-scan --deep [+] Gateway: 192.168.1.1 (Router) — OUI: NETGEAR [+] 192.168.1.5 DESKTOP-NEPTUNE — OUI: Intel ports 22,445 | OS: Linux [+] 192.168.1.23 MiBox4 — OUI: Xiaomi — Android 9 # custom interface and subnet, CSV export $ gnulte-scan -i wlan0 -C 192.168.0.0/24 -c > devices.csv

Documentation

Command line, parameters, profiles and settings.

# interactive: scan → select → configure → run $ sudo GNULTE # fast ARP-only scan $ sudo GNULTE --quick # deep port/OS scan of one IP $ sudo GNULTE --scan -t 192.168.1.20 # voip profile for 5 minutes $ sudo GNULTE -t 192.168.1.20 --profile voip --duration 300 # whole-subnet throttle, excluding your own devices $ sudo GNULTE -r 192.168.1.0/24 -w 192.168.1.1 --profile throttle --duration 600 # random chaos on your own test device + .pcap capture $ sudo GNULTE -t 192.168.1.20 --latency 1500 --jitter 800 --loss 5 --random --capture evid.pcap # detect duplicate IPs / ARP conflicts $ sudo GNULTE --dupcheck

Parameters

-l, --latency2000ms base delay
-j, --jitter500ms random variance
-p, --losspacket drop %
-d, --duplicateduplicate packet %
-e, --reorderout-of-order packet %

Themes & settings

  • Colour themes: classic, hacker, ocean, sunset, highcontrast, mono, custom
  • Verbosity: easy, normal, expert — expert shows every raw command and asks you to confirm it
  • Console log modes and a settings app via GNULTE --settings
  • Changes are saved to ~/.gnulte.conf

Reports & state

  • Post-test reports land in gnulte-report-<ts>/ with SVG latency graphs
  • Optional per-second CSV export via --export CSV
  • Disclaimer acceptance is stored in ~/.gnulte_accepted
  • --stealth hides GNULTE's presence on systems you own

Get GNULTE

Linux only. Requires root and iproute2, arp-scan and dsniff.

Download the source (ZIP) GitHub repository Releases

From the repo

# install to /usr/local/bin $ sudo install -m755 GNULTE /usr/local/bin/GNULTE $ sudo install -m755 gnulte-scan /usr/local/bin/gnulte-scan

Packages

  • Arch / AUR: cd packaging/aur && makepkg -si
  • Debian / Ubuntu: cd packaging/deb && dpkg-buildpackage -us -uc, then install the .deb — it ships /usr/bin/GNULTE, /usr/bin/gnulte-scan, a man page and docs

Authorised use only

GNULTE performs ARP spoofing to route traffic through your machine and kernel-level traffic shaping. Using it against networks or devices you do not own, or without authorisation, is illegal in most jurisdictions.

Use it on networks you own or have explicit written permission to test. You are solely responsible for your use. GNULTE is distributed under the GPL-3.0-or-later licence.
