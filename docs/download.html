Get GNULTE

Four commands, about two minutes. Linux only — root unlocks shaping and injection. See the WSL2 notes below.

Install

Step by step

STEP 1

Download the source

$ git clone https://github.com/notmicrosoft2000-cmd/gnulte-go.git

Copies the repository into a new gnulte-go/ folder in your current directory. You only need git (already installed on most distros).

STEP 2

Open the folder

$ cd gnulte-go

Moves you into the project directory, where the install script lives. Run every later command from here.

STEP 3

Build & install

$ ./install.sh

Builds all five binaries, verifies them, then installs to /usr/local/bin with docs under /usr/local/share/doc/gnulte-go/. It re-runs itself with sudo when needed, so you'll just be asked for your password. You need a Go toolchain and sudo — nothing else.

STEP 4

Check it works

$ gnulte --version

Should print GNULTE v13.0. The other four tools are now on your PATH too: gnulte-scan, gnulte-wifi, gnulte-traffic, gnulte-devices.

What you end up with

  • Five binaries in /usr/local/bin: gnulte, gnulte-scan, gnulte-devices, gnulte-traffic, gnulte-wifi
  • Safety documentation and the license under /usr/local/share/doc/gnulte-go/
  • Nothing is registered as a service or daemon — GNULTE only runs when you start it
  • First launch shows the safety documents and asks you to acknowledge them
Update

Two commands. Pulls the latest commits, then rebuilds and reinstalls.

$ git pull $ sudo ./install.sh
Uninstall

Removes the binaries and docs. Plain uninstall.sh keeps your config; --purge removes it too.

$ sudo ./uninstall.sh # also delete config + safety acceptance records $ sudo ./uninstall.sh --purge

From source

Building without installing

Build locally

Compiles the five binaries into the repo folder — no root, nothing installed. Tests and vet run first.

$ ./build.sh # writes ./gnulte ./gnulte-scan ./gnulte-wifi ./gnulte-traffic ./gnulte-devices

Needs a working Go toolchain; the script prefers ~/.local/bin/go if present, otherwise the system Go.

Requirements
  • A Linux distro with sudo
  • A Go toolchain (build only)
  • iproute2 — provides tc for traffic shaping
  • Root for shaping, ARP spoofing and Wi-Fi injection; a normal user can scan and inventory
  • arp-scan is optional — used opportunistically when running as root

Platform

Why GNULTE is Linux-only

GNULTE is built on Linux kernel networking interfaces that macOS and Windows don't expose. There is no port, and there won't be one — it needs the real kernel.

What it leans on

  • tc netem — kernel-level traffic shaping and latency injection (iproute2)
  • AF_PACKET raw sockets — GNULTE's built-in ARP spoofer speaks to the NIC directly for MITM tests
  • 802.11 monitor mode + frame injection — gnulte-wifi deauths from the driver level, not the app level
  • iptables/sysctl — IP forwarding while a shaping session relays traffic

What about Windows / macOS?

WSL2 runs a real Linux kernel in a VM, so the binaries will compile and execute there — but the network is the catch. WSL2's network card is a virtual adapter owned and NAT-ed by Windows:

  • No layer-2 access to your real LAN — ARP spoofing can't reach other machines
  • tc would only shape the VM's own connection, not your traffic
  • No monitor mode — Windows owns the Wi-Fi adapter, so injection is impossible
  • “Mirrored” networking still uses a synthetic adapter and doesn't change this

In short: WSL2 is fine for learning the CLI, not for testing a network.

Platform

Windows users — what to use instead

Dual-boot or native Linux

The full experience. Real NICs mean everything works — including Wi-Fi testing, as long as the wireless card supports monitor mode.

Recommended if you test Wi-Fi.

Linux VM, bridged network

VirtualBox / VMware / KVM with a bridged adapter puts the VM on your LAN at layer 2 — shaping and ARP spoofing work over ethernet.

Wi-Fi still needs a USB adapter passed through with monitor-mode support.

WSL2 (limited)

Good for evaluating the toolset and reading the docs. Scans/inventory only see WSL2's own virtual network — not a real test environment.

The core shaping, spoofing and Wi-Fi features don't work here.
