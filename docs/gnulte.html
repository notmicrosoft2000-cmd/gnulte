GNULTE/Tools/gnulte

gnulte

The core tester — route a target’s traffic through your machine and shape it on the wire with tc netem.

▶ Watch a re-enactment in Studio

The tester

What your devices feel when the network misbehaves

gnulte quietly interposes itself between a device and its gateway (ARP-spoofed routing), then applies kernel-level shaping with tc netem — latency, jitter, packet loss, duplication, reordering and bandwidth caps. Every target is pinged once per second while the test runs, and the whole session ends in an HTML report with SVG latency timelines.

Guided flow

Boot checks verify real results — privileges, interface, arpspoof, tc, ping and ip_forward — before a session is built. Then a menu walks you from target to parameters.

Pick your target

One IP, several IPs, a whole subnet (-r), a MAC (-m), or every device of a kind — --device-type phone,router or --vendor Apple.

Shape conditions

--latency 300 --jitter 30 --loss 5 — one flag per condition, plus 12 built-in profiles via --profile and live re-rolling with --random.

Self-healing

A spoof monitor revives arpspoof if it dies mid-test. Cleanup always runs — qdisc restored, forwarding restored, gateway ARP re-broadcast.

Quickstart

Two steps to your first test

# build all five tools from source (pure Go, no deps) $ cd gnulte-go && ./build.sh # install into /usr/local/bin (asks for sudo) $ sudo ./install.sh # run the guided menu (or skip it with flags) $ sudo gnulte # one-liner: 300ms latency + 30ms jitter, 90s auto-stop $ sudo gnulte -t 192.168.1.50 -l 300 -j 30 --duration 90

Root is required to shape traffic; the first launch prompts for sudo, and every ✓ in the boot banner is a live check.

Everyday shapes

Recipe-style flags

  • sudo gnulte -t 192.168.1.50 -l 300 -j 30 — sluggish-but-real latency
  • -p 8 / -d 2 / -e 3 — loss, duplication, reordering percent
  • -b 2048 — bandwidth cap in kbps (2 Mbps)
  • -r 192.168.1.0/24 -w 192.168.1.88 — whole subnet, whitelist your phone
  • --device-type phone --random — shape every phone, re-roll each second
  • --profile streaming — one of 12 presets (--list-profiles)
  • --traffic-window — open the GNULTE-LAN watch in a second terminal

Options

Key flags at a glance

The full set is always one --help away — this is the everyday subset.

FlagWhat it does
-t, --target IPTarget IP(s), comma-separated. Hostnames and .local names resolve.
-m, --mac MACTarget by MAC address instead of IP.
-r, --range CIDRTarget an entire subnet, e.g. 192.168.1.0/24.
-w, --whitelist IPExclude IP(s) from a range test.
--device-type KINDSTarget every LAN device of these kinds (phone,router,printer…).
--vendor NAMESTarget every LAN device matching a vendor (substring).
-l, --latency MSBase delay in ms.
-j, --jitter MSRandom variation around the base delay in ms.
-p, --loss %Packet drop percentage.
-d, --duplicate %Duplicate packet percentage.
-e, --reorder %Out-of-order packet percentage.
-b, --bandwidth KBPSBandwidth cap in kbps (0 = unlimited).
--profile NAMEApply a preset — 12 built-in profiles (--list-profiles).
--randomRe-roll latency / jitter / loss every second.
--duration SECONDSAuto-stop the test after N seconds.
--interval SECONDSPing interval (default 1s).
-c, --capture FILECapture the target’s traffic with tcpdump.
-S, --stealthStealth ARP spoofing — answer only when asked, slow jittered cache refresh.
--blockFully block the target’s traffic (no forwarding).
--export FILEStream per-second results to CSV while the test runs.
--traffic-windowWith 2+ targets, open the GNULTE-LAN watch in a separate terminal.

Safety is structural: it refuses to target the gateway or your own machine, verifies each parameter and estimates its impact out loud, and never leaves forwarding or a qdisc behind.
