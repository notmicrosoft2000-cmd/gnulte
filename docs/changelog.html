v16.0

Latest 29 Sep 2026
  • Ctrl+C exits cleanly instead of killing the run — a fix for the reported bug “I select multiple devices, pick monitor mode 1, press Ctrl+C and it kills rather than exits.” The toolkit’s shared signal handler was racing each tool’s own graceful shutdown and winning with a hard os.Exit(130), so a first Ctrl+C cut the session dead mid-teardown. It now restores the screen and terminal on the first signal and lets the shutdown finish, forcing the 130 exit only on a second Ctrl+C or after a grace period. This mattered beyond cosmetics: the old hard kill skipped sess.Stop(), so targets were left holding a poisoned ARP cache and lost connectivity.
  • The terminal always comes back — raw keyboard mode is now registered as a cleanup instead of being restored only on the normal path, so an interrupt can never leave you at a prompt with no echo and no working Enter.
  • gnulte-lan arrows do one thing — the reported phantom-repeat bug is gone. Holding an arrow key no longer “scoots” the cursor dozens of rows past where you pointed it: the app-side hold-repeat was removed in favour of your terminal’s own key-repeat, and two quick taps still queue and drain as two moves. Verified by a PTY regression test that replays single taps, quick taps and a 2.6-second hold.
  • Honest sampling cadence — the reported bug “when a ping takes longer than 1 second, the next one immediately fires”. A fixed-rate ticker starts every probe on schedule, so a slow probe left its tick already queued and the next one fired the instant the slow one returned: a 2-second target ran flat out with no gap at all. Both the single-target console and the multi-target dashboard now sample, show the reading, and then wait the full interval, so the one-second gap stays a one-second gap however slow the host is. A run also starts measuring immediately instead of after a blank second. Locked down by a test that drives the loops with a probe of a chosen duration and asserts the gap is probe time plus interval.
  • gnulte --note — label a run at launch (--note "pentest · building 4”). The note rides into the console header and the session report, so a month of reports still say which engagement they belonged to.
  • A live watch now stops when you tell it to — a second real bug, found while testing the above: interrupting a scan mid-sweep used to take up to 11 seconds to respond, because the name-identification waits (reverse DNS, mDNS, NetBIOS) bounded themselves by a deadline but never checked for cancellation — the exact shape signal.NotifyContext produces. Every wait now ends at once on cancel, and the per-host loops stop starting new lookups. Measured shutdown latency: 10.9s → 0.00s.
  • gnulte-scan --watch --json — a machine-readable feed for the same live rescan: one JSON object per sweep on stdout ({"kind":"baseline"} then {"kind":"delta"} with the movement), narrative to stderr, so gnulte-scan --watch 5 --json | jq is a working motion sensor. Mutually exclusive with -q/--yaml/--csv.
  • Quick scan — in the -T device table, r re-scans the subnet on demand and the status line grows a ▲ new ▼ gone ~ changed legend, so you can nudge the network and watch it react. The line leads with live state and keeps key hints last, because a narrow window truncates the tail first.
  • Quieter, clearer menus — devices the shared store already knows are marked * in the target picker, and you can select by keyword (Mobile, @hostname). gnulte-lan footers carry live counts on every screen, and the map keeps a legend.
  • Version 16.0 across all five binaries. Also fixed: GOOS=darwin builds now succeed (the ARP package declared two methods twice against a Linux-only field).

v15.0

29 Sep 2026
  • Live Interconnection — v13.5 → v15.0. The five tools now share one live view of the network, driven by a shared device store (~/.config/gnulte-go/devices.json): gnulte-lan folds every watch into the store (x saves, quit saves again), gnulte picks targets straight from it (w in the target menu), and gnulte-scan cross-references its summary and table against it. One watch feeds the whole toolkit.
  • gnulte-lan screen 5 — the interconnection map — the watch grows a fifth screen (5/m): every device becomes a node and live flows become edges, pulsing as traffic moves, re-arranged to a stable layout each tick. Like FLOWS it needs the raw capture socket, so a speeds-free run shows the explicit ⛔ needs the capture socket (root) gate with the sudo gnulte-lan remedy.
  • Handoff — pressing ⏎ (or g) on a host opens gnulte -t <ip> against it in a fresh terminal (falling back to printing the exact command when no terminal emulator is found). The detail pane moves to Tab/d; the map shows the ▸ pulse that follows the selected pair.
  • gnulte — live shaping telemetry — while a shaping run is live, the dashboard leans on tc -s qdisc and shows the netem live hand: dropped packets, backlog and limit directly from the kernel queue, polled on its own cadence and dimmed under the per-target live rows. The final snapshot is folded into the session report.
  • gnulte-scan --watch N — the scanner re-sweeps live on an interval: gnulte-scan --watch 5 re-discovers every N seconds and prints exactly what moved — ▲ new, ▼ gone, ~ changed — until Ctrl+C. In the -T full-screen browser the same cadence drives the table and marks each host with its delta marker; GONE hosts stay visible; the Summary window cross-references the shared device store. The interactive screen owns the watch, so quitting -T --watch exits cleanly (exit 0) instead of hanging on a second console loop.
  • Target-picker polish — gnulte-scan -T gains / filter focus (type to refine, Esc to clear) and v to filter by vendor, so one re-scan isolates a single maker’s devices.
  • Version 15.0 across all five binaries.

v13.5

28 Sep 2026
  • Four-screen console — the watch is now a real interactive console with ↑↓ host navigation and screen switching: 1 hosts (the live dashboard), 2 talkers (every host ranked by combined rate with down/up scale bars, peer counts, and a communicators block for LAN-internal pairs), 3 flows (the per-conversation table A ⇄ B with per-direction rates and a ⟷LAN tag for pairs that never leave the subnet), and 4 neighbours (the live ARP table: IP, MAC, vendor, device type, hostname and live ping for every device on the link, router included). Letter aliases t/f/n switch the same screens.
  • Sudo-gated sections — FLOWS needs the raw capture socket, so a speeds-free run explains itself instead of guessing: ⛔ needs the capture socket (root) with the exact sudo gnulte-lan remedy. Screen 2's byte ranking and screen 3's pairs are the root-only view; latency, identity and alarms always keep working.
  • One colour per IP — every host is assigned a stable hue in appearance order (red stays reserved for alarms), and that colour travels through the hosts, talkers, flows, ARP and detail panes — follow a device across the whole console by colour alone.
  • Scaled TUI, stable per run — rows adapt to terminal width: a compact two-line block below 78 columns, the familiar three-line block at normal sizes, and a four-line “MORE” variant at 116+ columns that adds p50/p95 latency and a per-host session line (session/peak averages, lifetime bytes). Height only changes on a real resize, then holds.
  • More information — the header now shows the LAN-wide net rate (net ↓ x · ↑ y) on every tick; the detail pane gains p50/p95 latency, the host's share of the net, and stays one keystroke (⏎/Tab) away; Esc peels layers (close pane → back to hosts → quit).
  • Root socket required and wanted — run plain for the passive watch, or with sudo gnulte-lan for byte-accurate flows, talkers and net rates (the watch auto-elevates via sudo).
  • Version 13.5 across all five binaries.

v13.4

28 Sep 2026
  • Watch polish — gnulte-lan becomes a smooth, stable monitor you can trust while picking test targets: every host now occupies a fixed three-line block (traffic+latency, identity, session health), so rows neither grow nor shrink between ticks and the frame never jumps around.
  • Pick-a-target grades — each row carries a one-glyph health verdict (✓ stable, ~ jittery or lossy, ✗ flaky, ⚠ alarming) plus jitter, loss and whole-watch average speeds, so a good GNULTE test device is obvious at a glance.
  • Test-recipe button — the detail pane ends with test with: gnulte -t <ip>, and pressing g echoes that exact command under the footer. The watch is explicitly the “choose your target” half of the toolkit now.
  • Header health line — the status bar gains hosts-up count and a self · gateway ←→ RTT line (the gateway is pinged alongside the watch), so “is my uplink fine?” is answered without opening anything.
  • Smooth keyboard — pings run in the background and results land between ticks, so a slow or silent host can never freeze the arrows; holding ↑/↓ scrolls fast just like htop (raw terminals deliver no auto-repeat).
  • Locked columns — rate, latency and health cells are fixed-width everywhere (the alarm badge reserves its own column), and aligned totals replace the old cut-off line.
  • Version 13.4 across all five binaries.

v13.3

28 Sep 2026 · 497cda7
  • Banner & boot polish — gnulte-lan opens with the GNULTE-LAN block wordmark, a purpose line that answers “what is this for?”, and width-aware boot notes (skipped with -q).
  • Arrow keys work — the watch is now a real interactive screen: ↑/↓ move a host cursor, and the live frame redraws instantly between ticks.
  • Host detail pane — ⏎/Tab opens a per-host card: MAC/vendor/type/hostname, down/up with session peaks, latency min/avg/max/loss, three relative sparklines (latency, down, up), and the host's top conversations this interval.
  • Sort, filter, panes — s cycles traffic → latency → address order, a filters to only the alarming hosts, t toggles the global top-talkers pane, and h expands the key hints footer.
  • Options mid-watch — o opens the settings editor live: interval, history depth, timeout, alarm thresholds and beeps apply to the running watch without a restart.
  • Scroll-safe frames — the host window is packed by line budget (not row count), so sparse multi-line rows fit any terminal height, the cursor never leaves the screen, and ▴/▾ indicate hidden hosts.
  • Self-explaining help — --help now leads with gnulte-lan's purpose and ends with examples; the tool's doc comment tells the full story.
  • tui.KeyStream.Poll — new non-blocking key decode in the shared terminal library (arrows, ⏎, Esc, runes) that never drops a queued sequence; used by the interactive watch.
  • Version 13.3 across all five binaries.

v13.2

28 Sep 2026 · 0944a3a
  • GNULTE-LAN — gnulte-traffic is renamed gnulte-lan and grows into a full live LAN watch: per-host down/up speed, packet rate and latency, refreshed every interval.
  • Auto-discovery — with no -t, gnulte-lan sweeps the subnet in seconds and watches every live host, merging ARP-table neighbours so ping-silent devices still appear — while always skipping your own machine and the gateway.
  • Identity layer — each watched host is labelled with MAC, vendor (embedded OUI), device type and hostname from the ARP+neighbour table and mDNS.
  • Top talkers — a passive per-interval flow engine (AF_PACKET, TCP/UDP port parsing) shows which endpoints are exchanging the most bytes and packets, bolded when a watched host is involved.
  • Lightweight alarms — rate (kbps) and latency (ms) thresholds, set in the settings editor or via --alarm-rate/--alarm-latency-ms; one beep per tick and a ⚠ marker on offending hosts. Zero disables.
  • CSV export — --export file.csv appends a row per host per tick (rates, packets, RTT, loss).
  • HTML report — the session report gains per-host cards with rate + latency sparklines, each host's top-5 conversations, and a global top-talkers table.
  • Speeds-free fallback — without root the packet counter degrades gracefully (window warns once) and latency/identity/talkers still run.
  • Version 13.2 across all five binaries.

v13.1

  • Router-safe ranges — -r sweeps and the guided “all devices” pick never target the gateway (shaping the router would cut your own uplink). It stays selectable by number when you really mean it.

  • Polished session report — the SVG report is renamed gnulte-go-scan-report-<date>-<time>-<count>.html and redone: UP / DEGRADED / UNSTABLE status pills, a sorted target-summary table, and per-target cards with area-filled latency timelines, timeout markers and headline stats, above the full command history.

v13.0

27 Sep 2026 · 2642181
  • Stealth ARP spoofing — gnulte -S/--stealth uses a built-in AF_PACKET spoofer that answers only when asked and re-arms target caches on a slow, jittered ~30 s schedule. Far less visible to other scanners on the LAN; drops the arpspoof(8) dependency in stealth mode.
  • Wi-Fi testing that sticks — gnulte-wifi gains per-frame timing jitter (--jitter-ms, defeats reconnect timers), rotating deauth reason codes (--mix), channel-hopping (--hop-channels/--channels), and a second Ctrl+C to force-quit the summary.
  • ARP discovery — gnulte-scan automatically sweeps the subnet when run as root, so hosts that block ping still show up.
  • Tabbed monitor — gnulte-scan -T is now a Devices / Log / Summary window set (Tab or 1/2/3), with o opening the settings page from inside the scanner.
  • Per-target traffic windows — gnulte --traffic-window opens one monitor terminal per target when shaping several devices at once.
  • Settings TUI — a categorized full-screen editor (jog/toggle keys, reset) across the tools; StealthArp preference added.
  • Reports hub — all tools file HTML reports into ~/GNULTE Reports, with an interactive y/N ask on interactive runs; the engine command transcript now prepends the report log.
  • Clean exits — sessions always tear down sessions (defer-based stop), so spoofs and shapers are restored even on nested returns.
  • SCANLTE — gnulte-scan gets the rebrand: ASCII block logo and “side tool for GNULTE” tagline.
  • Avahi-style service discovery — gnulte-scan asks the LAN's mDNS/DNS-SD responders (single two-phase PTR→SRV/A exchange) what each device offers: airplay, chromecast, homekit, matter, ssh, printer, scanner, vnc and more. Advertised services appear in a SERVICES column, the interactive detail pane and filter, JSON/YAML/CSV exports, and the scan summary.
  • Ping history per host — the monitor dashboard and gnulte-lan (then gnulte-traffic) keep a rolling latency window per target, with a block sparkline under each live traffic row (last RTT, average, loss). Depth is configurable (ping history depth, 10–240).
  • Settings that scale — the settings TUI adapts to wider terminals (up to ~96 columns) and regroups every option under dim section headers (Network & Monitor, Scanlte Scan, Traffic Engine, GNULTE-WIFI, Terminal & UI), with g/G first/last keys and header-skipping navigation.
  • Advanced mode — a settings toggle controls whether gnulte echoes the exact command line for every tc/arpspoof/sysctl step as it runs; the HTML report transcript records them either way.
  • Typing animation — on live terminals the interactive confirmation is typed out character by character (instant when piped or quiet).
  • Version 13.0 across all five binaries.
