Features

Network testing the way network testing should be done.

Capabilities

What GNULTE does

LAN scanning

Scans your network in parallel and fingerprints every device with the shared identification engine — OUI vendor from an embedded registry (plus system files as fallback), mDNS .local names and reverse DNS, NetBIOS name lookups, open ports, device type and an OS fingerprint from TTL, banners and port signals. Routers, phones, TVs, printers, cameras and IoT, all labelled and colour-coded by type in the scan table, with a full-screen interactive browser via -T (Devices / Log / Summary windows, o opens the settings page). When run as root it also sweeps by ARP so hosts that block ping still show up.

Flexible targeting

Select one IP, several IPs, an entire subnet, or resolve a target from its MAC address, hostname or .local name. Filter by device type (--device-type) or vendor (--vendor). Whitelist your own devices and range tests skip them automatically. In the guided flow you're asked first whether you'd rather type an IP by hand, and range sweeps and the “all devices” pick always leave the router out of it (it's your way in and out, not a test target).

Traffic shaping

IP forwarding on, ARP spoof routing the target through your machine, and tc netem applied on the wire: latency, jitter, loss, duplication, reordering and bandwidth. Bandwidth caps chain underneath the qdisc, so shaping is never lost. Spoofing can run in stealth mode (-S): an in-Go, on-demand ARP spoofer answers only when asked and re-arms caches on a slow jittered refresh, so other scanners on the LAN see far less activity.

Parameter validation

Every parameter is validated before it runs and its impact is estimated out loud before applying. It refuses to target the gateway or your own machine.

Live dashboard

Every target is pinged once per second during a run — last, min, max, average and loss — rendered live with a full-screen, full-data view. While a shaping run is live, the dashboard also reads tc -s qdisc and shows the netem live line: dropped packets, backlog and limit straight from the kernel queue.

Live LAN watch

gnulte-lan is a full interactive console: with no -t it discovers the subnet in seconds, opens its GNULTE-LAN banner, and repaints the LAN every interval — per-host down/up speed, packet rate and latency, each row labelled with MAC, vendor, device type and hostname. It is a five-screen console, switched with 1–5 (or t/f/n/m): 1 hosts — the dashboard, every host a fixed-shape block (traffic+latency, identity, session health) that never jumps between ticks, with a one-glyph grade (✓ stable, ~ jittery, ✗ flaky, ⚠ alarming); 2 talkers — every host ranked by combined rate with down/up scale bars, peer counts, and a communicators block for LAN-internal pairs; 3 flows — the A ⇄ B conversation table with per-direction rates and a ⟷LAN tag, gated behind the root capture socket with an explicit sudo gnulte-lan hint; 4 neighbours — the live ARP table (IP, MAC, vendor, type, hostname, ping) including the router; 5 map — the Live Interconnection map, devices as nodes and live flows as edges that pulse (▸) with traffic, also gated behind the root socket. Every IP keeps one stable colour across all screens so you can follow a device by hue; rows scale with terminal width (compact, normal, a 4-line MORE variant at 116+ columns with p50/p95 and session totals). The header adds a hosts-up count, the gateway's live RTT and the LAN-wide net rate. ↑/↓ move the cursor (hold to scroll fast), ⏎ (or g) hands the selected host off to gnulte -t <ip> in a fresh terminal, Tab/d opens the detail pane (p50/p95, net share, flows), x saves the whole watch to the shared device store, s re-sorts, a filters to alarming hosts, o edits settings live, Esc peels panes/screens before quitting. Lightweight rate/latency alarms flag problem hosts; --export streams per-tick CSV and the session files an HTML report with per-host sparklines. Runs speeds-free without root; root unlocks flows, byte-accurate talkers, net rates and the live map.

Live interconnection

The tools are wired together by one shared device store (~/.config/gnulte-go/devices.json): gnulte-lan folds every watch into it (x, and again when you quit), gnulte offers its targets straight from it (w in the target menu), and gnulte-scan marks how much of its table the store already knew — in both the -T Summary window and the live --watch feed. One watch feeds the whole toolkit.

Instant inventory

gnulte-devices turns the ARP/neighbour table into a full device list with vendors, mDNS names and types — no sweep, no root, in a single pass.

Reports & capture

Every session ends in an HTML report — gnulte-go-scan-report-<date>-<time>-<count>.html — with per-target SVG latency timelines, UP/DEGRADED/UNSTABLE status pills, a sorted target-summary table and the full console log, filed into a ~/GNULTE Reports hub (a per-tool folder per report). Scan and inventory tools export JSON, YAML, CSV or a standalone HTML report. Capture traffic with --capture, or stream per-second CSV with --export. Interactive runs are asked first before a report is written.

Self-healing

The spoof monitor watches arpspoof and revives it if it dies mid-test. Targets are verified reachable first, and cleanup always runs — qdisc restored, spoof processes killed, IP forwarding restored, gateway ARP re-broadcast.

LAN hygiene

--dupcheck detects duplicate IPs and ARP conflicts; --minimal/--no-banner give a plain startup; twelve presets (--list-profiles) reproduce conditions exactly, with a numbered picker during setup — a bare Enter goes straight to manual values.

Discreet spoofing

Classic spoofing heartbeats unsolicited ARP replies every few seconds. Stealth mode (-S) answers only when a victim asks who owns the gateway (or the gateway asks about a victim), arms each cache once, then re-freshens on an irregular ~30s jittered schedule — ordinary-looking traffic to anyone sweeping the LAN.

Wi-Fi testing

gnulte-wifi injects targeted 802.11 deauthentication frames for authorized disassociation testing, with per-frame jitter so the timing is irregular, rotating deauth reason codes each burst, and an optional channel-hopping mode (--hop-channels) that swims the adapter across the configured channels — plus a second Ctrl+C to force-quit during the summary.

Settings editor

One settings TUI (--settings, or o inside the interactive scanner) organizes every tunable into categories — beeps, report behaviour, ARP sweep, Wi-Fi timing, stealth spoofing. Scroll, jog integers with ←/→, toggle booleans, reset current or all, with a help footer per item.

Workflow

From scan to report

Four steps, a live dashboard in the middle, and a report on the way out.

STEP 01

Complete the safety onboarding

On first run GNULTE shows the legal and safety documents. Acknowledgment is persisted to ~/.config/gnulte-go/acceptance.json, tied to a document version, and required again if the documents change.

STEP 02

Scan and select

Interface, gateway and IP are detected, then the network is scanned. Pick a target, several, or a subnet.

STEP 03

Shape the link

Forwarding is enabled, arpspoof reroutes the target, and tc netem applies the conditions you chose.

STEP 04

Verify and clean up

The dashboard pings every second; when it's over, everything is removed and a report with SVG graphs is written.
