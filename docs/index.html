GNULTE

GNU LAN Network Testing Environment

A toolkit of focused Linux tools, written in Go.

A suite that reroutes a target's traffic through your machine and applies kernel-level shaping with tc netem — so you can measure how devices behave under real latency, jitter, packet loss and bandwidth limits. Companion tools discover (gnulte-scan), inventory (gnulte-devices), watch the LAN live (gnulte-lan) and audit Wi-Fi (gnulte-wifi). The tools interconnect: one live watch folds into a shared device store every tool reads. It scans first, asks permission first, and cleans up after itself.

The toolkit

One suite, five focused tools

From discovery to a finished report — every step of testing your LAN has a dedicated binary, plus a browser studio to see them all before installing.

gnulte

The core tester — ARP-spoof routing plus tc netem latency, jitter, loss, duplication, reordering and bandwidth caps, with a live dashboard, live shaping telemetry straight from tc -s qdisc, and an HTML report. Targets can be picked straight from the last LAN watch (w).

gnulte-lan

The LAN watch — a five-screen console: hosts with live down/up speed, packet rate, latency and a health grade (one stable colour per IP), talkers ranked with bars and peers, per-pair flows, a live ARP neighbours table, and screen 5's interconnection map with live pairs pulsing as edges. Passive, width-scaled and root-ready. Press ⏎ on a host to hand off straight into gnulte -t <ip>, or x to fold the whole watch into the shared device store.

gnulte-scan

The scanner — sweep or read the neighbour table; vendor from the embedded OUI registry, mDNS names, open ports and a type guess. Root optional. Re-scan live with --watch N and watch the network move — ▲ new, ▼ gone, ~ changed — or browse it in the -T full-screen browser.

gnulte-wifi

Wi-Fi audit — crafted 802.11 deauthentication frames from monitor mode, with burst control, reason-code mixing and jitter. Authorized testing only.

gnulte-devices

Instant inventory — the ARP/neighbour table becomes a full device list in one pass, enriched with vendors, mDNS names and types. No sweeps, no root.

Capabilities

Built for real networks

A terminal tool that treats testing seriously.

LAN scanning

Sweep or read the neighbour table — devices come back with vendor from an embedded OUI registry, mDNS .local names, reverse DNS, open ports and a type guess. Routers, phones, TVs and IoT, all labelled.

Targeting

One IP, several IPs, a whole subnet, or an IP looked up from a MAC. Whitelist your own devices and range tests skip them automatically.

Traffic shaping

Latency, jitter, loss, duplication, reordering and bandwidth via tc netem, with caps chained so nothing is dropped. --duration auto-stops runs; --random varies conditions live.

Validation

Every parameter is checked before it runs and its impact is estimated out loud. It refuses to target the gateway or your own machine.

Live dashboard

Every target is pinged once per second — last, min, max, average and loss, and the report is an SVG graph of the whole run. While shaping, a netem live line reads the kernel queue (tc -s qdisc) so you see the hand your own network conditions are dealing.

Live interconnection

gnulte-lan's screen 5 draws the LAN as a live map — devices as nodes, live flows as pulsing edges — and its x/auto-save folds every watch into the shared device store. gnulte picks targets straight from that store (w) and gnulte-scan cross-references its table and summary against it. One watch feeds the whole toolkit.

Self-healing

The spoof monitor revives dead arpspoof processes mid-test. Targets are verified reachable first, and cleanup always runs — previous qdisc and ip_forward value restored.
