Start here

Getting started

Installation is four commands — see the step-by-step guide and the Linux / WSL2 notes.

$ git clone https://github.com/notmicrosoft2000-cmd/gnulte-go.git $ cd gnulte-go $ ./install.sh $ gnulte --version

First run

Launch sudo gnulte. On the very first run it shows the safety documents (SAFETY, AUTHORIZED-USE, DISCLAIMER) and asks you to acknowledge them; the record persists in ~/.config/gnulte-go/acceptance.json (see --reset-safety).

Elevation

Tools that need root re-run themselves via sudo with a single prompt. Discovery and inventory (gnulte-scan, gnulte-devices) work as a normal user. gnulte-lan elevates for its packet counters but still watches latency and identity speeds-free without root.

Typical session

Scan the LAN → pick a device → choose a profile (or hand-tune parameters) → watch the dashboard → one Ctrl+C restores everything. That flow is the whole stride of gnulte.

Under the hood

How it works

1

Discover

Reads the kernel’s neighbour table and sweeps the subnet in parallel. Identifies hosts by OUI vendor, mDNS and NetBIOS names, device-type heuristics and OS fingerprints.

2

Intercept

Spoofed ARP puts this host in the middle of the target’s traffic (MITM). Stealth mode sends only directed arming frames and answers when asked — near-invisible to other scanners.

3

Shape

A tc netem qdisc at the interface applies latency, jitter, loss, reorder, duplication and bandwidth caps — kernel-level, per packet, as the target’s real link would behave.

4

Monitor & clean up

Live per-second dashboard (one terminal per target with --traffic-window). On exit — graceful or not — spoofs and qdiscs are restored and reports are filed.

On Wi-Fi, gnulte-wifi works differently: it injects 802.11 deauthentication frames with the AP’s BSSID as source, so the victim station drops its association — the “kick client” behaviour of a router, reproduced for authorised testing. It needs an interface in monitor mode.

Reference

The five tools

gnulte

The MITM + shaping engine. Interactive wizard; target by IP (-t), MAC (-m), range (-r), type (--device-type) or vendor (--vendor). Profiles, -S/--stealth, --dupcheck, --capture, --export, --block, --random, --duration.

gnulte-scan (SCANLTE)

Parallel subnet scanner with in-Go port scanning (-d), multi-signal OS fingerprints, automatic ARP sweep as root, -T tabbed monitor (Devices/Log/Summary, o = settings), JSON/YAML/CSV export, HTML report hub.

gnulte-devices

Instant ARP / neighbour inventory: vendors, mDNS names, type guesses, HTML reports. Add -s to sweep the subnet in parallel too.

gnulte-lan

Live LAN watch. With no -t it discovers the whole subnet in seconds (router and self skipped), opens its banner, then repaints the LAN every interval — per-host down/up speed, packet rate and latency with device identity: MAC, vendor, type, hostname. It is a five-screen console: 1 hosts (the dashboard), 2 talkers (ranked by combined rate with down/up bars, peers and LAN-internal communicators), 3 flows (per-pair A ⇄ B with per-direction rates, root socket), 4 neighbours (the live ARP table with vendor, type and ping) and 5 map (the Live Interconnection map — devices as nodes, live flows as pulsing edges, root socket). ↑/↓ move a host cursor (hold to scroll fast), ⏎ (or g) hands the host off — it opens gnulte -t <ip> in a fresh terminal or prints the exact command when no terminal emulator is found — Tab/d opens the detail pane (p50/p95 and net share), x saves the whole watch to the shared device store (~/.config/gnulte-go/devices.json), s re-sorts by traffic/latency/address, a filters to alarming hosts, 1–5 (or t/f/n/m) switch screens, Esc peels a pane or returns to hosts, o edits settings live. Every IP keeps one stable colour across screens; rows scale with terminal width (compact two-line, standard three-line blocks, or a four-line MORE variant with p50/p95 and session totals at 116+ columns). The header shows hosts up, the gateway's live RTT and the LAN-wide net rate. Lightweight alarms flag hosts over a rate or latency threshold; --export streams CSV and the session files an HTML report. Root unlocks screens 2–3 and 5's byte-accurate talkers, flows, net rates and the live-edge map (speeds-free runs show a polite ¡ speeds-free note, and FLOWS/MAP explain the sudo gnulte-lan requirement). gnulte-lan -t 192.168.1.20 --duration 60 for a single target.

gnulte-wifi

802.11 deauth for authorised Wi-Fi testing. -i monitor interface, -a AP BSSID, -s station (“all” = ff:ff:ff:ff:ff:ff). --mix rotates reason codes, --jitter-ms defeats reconnect timers, --hop-channels keeps a hopping AP in range.

Common tasks

Recipes

Throttle a console or video device

# dial-up-grade link for 10 minutes, keep your own machine out of it $ sudo gnulte -t 192.168.1.20 -w 192.168.1.100 --profile throttle --duration 600

Simulate a bad VoIP call

$ sudo gnulte -t 192.168.1.20 --profile voip --duration 300 --stealth

Stealth keeps the spoofing quiet on the LAN while the voice link degrades.

Find hosts that ignore ping

# as root: the ARP sweep catches ICMP-blocking hosts automatically $ sudo gnulte-scan -C 192.168.1.0/24 # or deep-scan the survivors for open ports $ sudo gnulte-scan -C 192.168.1.0/24 -d

Check for duplicate / conflicting IPs

$ sudo gnulte --dupcheck

Scans the LAN for ARP conflicts and exits.

Watch a live link without shaping

# watch two hosts, or no -t to discover and watch the whole LAN $ gnulte-lan -t 192.168.1.20,192.168.1.21 --duration 90

Authorised Wi-Fi “kick” test

# monitor mode interface, AP BSSID, one victim, rotating reasons + jitter $ sudo gnulte-wifi -i wlan0mon -a 00:0c:41:63:45:6a -s aa:bb:cc:dd:ee:ff --mix --jitter-ms 40 # keep kicking even while the AP hops channels (all clients) $ sudo gnulte-wifi -i wlan0mon -a 00:0c:41:63:45:6a -s ff:ff:ff:ff:ff:ff --hop-channels --channels 1,6,11

Answers

FAQ

Is GNULTE legal to use?

Only on networks you own or have written permission to test. First launch shows the safety documents and requires an acknowledgement. The license governs copying and distribution — not your conduct — and disclaims all warranty and liability; illegal use remains illegal and is your responsibility.

Why does shaping need root?

Installing the tc netem qdisc and sending raw AF_PACKET ARP frames both require privileges. Tools prompt for sudo once at launch; discovery/inventory tools run unprivileged.

Why is GNULTE Linux-only? Does it work in WSL2?

It builds on Linux kernel networking — tc netem, AF_PACKET raw sockets, iptables forwarding, and 802.11 monitor-mode injection. WSL2 can run the binaries but its virtual NAT card offers no layer-2 access and no monitor mode, so the core features don’t work there. See the Linux / WSL2 notes.

Can it test Wi-Fi clients?

gnulte-wifi deauths stations using a monitor-mode wireless adapter — the same capability a router’s “kick client” uses. For shaping-based MITM over Wi-Fi, client isolation on the access point can prevent it; ethernet links have no such barrier.

Will it touch my gateway or my own machine?

No — the gateway and your own host are refused as targets by the safety rails, and parameter validation estimates impact before anything is applied.

How do I stop a run cleanly?

One Ctrl+C stops gracefully and restores everything (spoofs replaced by gratuitous ARP, qdisc removed). A second Ctrl+C force-quits a hung summary. After any run, a normal ping to the target confirms traffic is back to normal.

Where do reports and state live?

HTML reports are filed into the ~/GNULTE Reports hub (gnulte → GNULTE go!/, gnulte-scan → Gnulte-scan/), with an interactive y/N ask on interactive runs. Config and settings live in ~/.config/gnulte-go/; the safety acknowledgement is acceptance.json there.

Does it phone home or collect data?

No telemetry of any kind — everything runs locally and offline. The only “network → disk” flows are the packet capture (--capture) and reports you explicitly enable or accept.

How do I update or remove it?

Update: git pull then sudo ./install.sh. Remove everything: sudo ./uninstall.sh --purge (binaries, docs, and the safety record; config is left in place). Full steps on the download page.

I found a bug or want a feature?

Open an issue on GitHub — include the tool, version, flags used, and what the LAN looked like (interface, subnet) if relevant.

Fixes

Troubleshooting

“operation not permitted” / can’t shape

Run with sudo (tools re-elevate themselves). If the first-run safety acknowledgement was skipped, gnulte --docs reviews it and --reset-safety re-arms the prompt.

tc not found

Install iproute2 (sudo apt install iproute2, dnf install iproute, pacman -S iproute2). The tc binary is how shaping is applied.

The scan shows nothing

Check you’re scanning the right interface (-i) and subnet (-C). Run as root so the ARP sweep catches ping-blockers, and try -d to deep-scan survivors for open ports.

No monitor mode for Wi-Fi

The adapter or driver doesn’t support it. You need a wireless card with monitor-mode support and a driver exposing it (e.g. mac80211); bring the interface up with iw before handing it to gnulte-wifi -i.

Target shows unreachable over ICMP

Hosts can block ping while still answering TCP. Fallback probe ports (default 443,80,53 via --probe-ports) keep identification working, and the root ARP sweep sees them regardless.

Shaping left in place after a crash

Usually the tools restore themselves on exit. If a hard crash left a qdisc behind, clear it manually: sudo tc qdisc del dev eth0 root (use your real interface).

Before you run

Safety checklist

1

Permission

Have written authorisation for every network you test. “It’s my office / my ISP” isn’t a legal defence — ownership matters.

2

Read the docs

Accept the safety documents on first run; re-read gnulte --docs any time. Remember the gateway and your own host are off-limits by design.

3

Limit blast radius

Target a single device or subnet with -w whitelists, use --duration for auto-stop, and prefer gentle profiles when unsure.

4

Record evidence

Capture the run: --capture evid.pcap, --export data.csv, and the HTML report that lands in ~/GNULTE Reports.

After every run: stop gracefully (one Ctrl+C), ping the target to confirm the link is restored, and verify the tc qdisc and spoofs are gone. File the report. Clean up after yourself.

Reference

Glossary

ARP
Address Resolution Protocol — maps IP addresses to MAC addresses on a LAN.
Spoofing
Sending ARP frames that claim — falsely, for testing — that an IP belongs to a different MAC.
MITM
Man-in-the-middle: routing a target’s traffic through this host so it can be shaped.
netem
Linux kernel network emulator — applies delay, jitter, loss, reorder, duplication.
qdisc
Queuing discipline — the per-interface traffic policy tc installs.
Deauthentication
A management frame that ends a station’s Wi-Fi association.
Monitor mode
Wireless mode where the card sees and transmits raw 802.11 frames.
OUI
Organisationally Unique Identifier — the vendor prefix of a MAC address.
mDNS
Multicast DNS — resolves .local device names on the LAN.
NetBIOS
Legacy name service still used by many LAN devices.
Fingerprinting
Identifying an OS from its packet behaviour and TTL/timestamp signatures.
RTT
Round-trip time — the ping latency the dashboard tracks.
Jitter
Random variance added to latency — makes a link feel “unstable”.
AF_PACKET
Linux raw-socket domain GNULTE uses to build and send its own frames.
Stealth ARP
Spoofing that answers only when asked, with slow jittered refreshes — far less visible to other scanners.
Acceptance record
The saved first-run acknowledgement of the safety documents.
