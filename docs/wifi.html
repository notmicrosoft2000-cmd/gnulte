gnulte-wifi

Targeted station disconnection for authorized Wi-Fi testing — crafted 802.11 deauthentication frames from a monitor-mode adapter.

▶ Watch a re-enactment in Studio

The audit

The “kick a client” control, reproduced

A deauthentication frame is crafted with the source MAC set to the access point’s BSSID and the destination set to one victim station. The station assumes its router disconnected it and drops the Wi-Fi association. Repeated bursts keep kicking a client that rejoins — a router’s “kick client” behaviour, reproduced for authorized testing on networks you own.

Monitor mode

Point an adapter already in monitor mode at the network: -i wlan0mon. Airdecap-style setup (airmon-ng start / iw dev set type monitor) is expected.

Burst control

Frames per burst (--count, default 64), seconds between bursts (--delay), and --once for a single shot.

Hard to filter

--jitter-ms defeats reconnect timers, --mix rotates the reason code each burst, --hop-channels keeps a channel-hopping AP in range.

Safety rails

Interactive confirmations before a burst (--force skips them), a saved --settings page, and built-in safety documents (--docs).

Usage

One command

# put an adapter into monitor mode first $ sudo airmon-ng start wlan0 # kick one station off its AP (run only on your own gear) $ sudo gnulte-wifi -i wlan0mon -a 00:0c:41:63:45:6a -s aa:bb:cc:dd:ee:ff # eject every client, mix reason codes, hop channels $ sudo gnulte-wifi -i wlan0mon -a 00:0c:41:63:45:6a -s ff:ff:ff:ff:ff:ff --mix --hop-channels # single 120-frame burst to test a reconnect timer $ sudo gnulte-wifi -i wlan0mon -a 00:0c:41:63:45:6a -s aa:bb:cc:dd:ee:ff --count 120 --once

Responsibility

Authorized testing only

gnulte-wifi sends frames that disconnect real clients. Use it only on networks and devices you own or are explicitly paid / permitted to test. The tool prints a safety record on first run, keeps a --reset-safety acceptance gate, and is built to make the “am I allowed to do this?” question impossible to skip silently.

Some adapters cap injection rates — raise --count if a single frame rarely lands. The tool never associates to an AP; it only listens in monitor mode and emits.

Options

Fine control of the burst

FlagWhat it does
-i, --interface IFACEWireless interface in monitor mode (e.g. wlan0mon).
-a, --ap MACAccess point BSSID (the router’s MAC).
-s, --station MACStation to disconnect; ff:ff:ff:ff:ff:ff = all clients.
--reason CODEDeauth reason code (default 7 = STA leaving BSS).
--count NFrames per burst (default 64).
--delay SECONDSSeconds between bursts (default 5).
--jitter-ms NRandom 0–N ms delay before each frame (defeats reconnect timers; 0 = no jitter).
--mixRotate the reason code each burst (default on; off when --reason is set).
--hop-channelsHop the adapter through a channel list after each burst.
--channels LISTHop list, comma-separated (default 1,6,11).
--onceSend a single burst and exit.
--duration SECONDSAuto-stop after N seconds (0 = until Ctrl+C).
--forceSkip interactive confirmations.
-q, --quietResults only.
