Quick start

Run it as root

Traffic shaping needs root (ARP spoofing + tc netem); discovery and inventory tools run as a normal user.

# interactive: scan → select → configure → run $ sudo gnulte # one device, voip profile, auto-stop after 5 minutes $ sudo gnulte -t 192.168.1.20 --profile voip --duration 300 # whole subnet throttled, excluding your device $ sudo gnulte -r 192.168.1.0/24 -w 192.168.1.100 --profile throttle --duration 600 # full-screen settings editor (colours, defaults, log mode) $ sudo gnulte --settings # detect duplicate IPs / ARP conflicts, then exit $ sudo gnulte --dupcheck

--randomwander parameters during a run
Profiles

Save your own combos with --save-profile NAME and replay them any time. The full flag reference lives in gnulte --help.

Companion tools

The full toolbox

One shared identification engine, five focused binaries.

gnulte-scan

Parallel subnet scan + in-Go port scanner with --deep. mDNS .local names, embedded OUI vendor, device types, HTML reports and JSON / YAML / CSV.

gnulte-devices

Instant ARP/neighbour inventory — vendors, mDNS names, type guesses, HTML reports. Add -s to sweep the subnet in parallel too.

gnulte-traffic

Live per-second latency + jitter + loss to one or several targets — a lightweight companion to the full shaping engine.

Operational

Evidence, state and safety

How runs start, what they produce, and what they refuse to do.

Reports

Output lands in gnulte-session-ts.html — SVG latency charts with the full live console log, ready to attach to a ticket or paste into documentation.

Capture & export

--capture evid.pcap stores a packet capture of the whole test. --export CSV writes per-second dashboard data for external analysis.

Safety & state

Versioned safety acceptance persists in ~/.config/gnulte-go/acceptance.json; the documents (SAFETY.md, DISCLAIMER.md, AUTHORIZED-USE.md, NETWORK-TESTING.md, FIRST-RUN-NOTICE.md) live alongside LICENSE in the repository and are bundled at install time. Editor defaults live in ~/.config/gnulte-go/settings.json.

Safety rails

Parameter validation estimates impact before applying. The gateway and your own machine are refused as targets, and every run ends in a full cleanup.

Verification

Targets are verified reachable before shaping starts, and the spoof monitor revives dead arpspoof processes mid-test so runs complete.

Settings

sudo gnulte --settings opens a full-screen colour editor with live preview: themes (classic, hacker, ocean, sunset, highcontrast, mono, custom), verbosity (easy, normal, expert) and console log mode. Saved defaults live in ~/.config/gnulte-go/settings.json.
