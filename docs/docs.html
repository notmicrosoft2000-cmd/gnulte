Quick start

Run it as root

GNULTE requires root and a few command-line companions: arp-scan, dsniff and iproute2.

# interactive: scan → select → configure → run $ GNULTE # one device, voip profile, auto-stop after 5 minutes $ GNULTE -t 192.168.1.20 --profile voip --duration 300 # whole subnet throttled, excluding your device $ GNULTE -r 192.168.1.0/24 -w 192.168.1.100 --profile throttle --duration 600 # deep port/OS scan of one IP $ GNULTE --scan -t 192.168.1.20 # detect duplicate IPs / ARP conflicts $ GNULTE --dupcheck

Operational

Evidence, state and safety

How runs start, what they produce, and what they refuse to do.

Reports

Output lands in gnulte-report-<ts>/ with SVG latency graphs and a status summary. Ready to attach to ticket or paste into documentation.

Capture & export

--capture evid.pcap stores a packet capture of the whole test. --export CSV writes per-second dashboard data for external analysis.

Safety & state

Versioned safety acceptance persists in ~/.config/gnulte/acceptance; the documents (SAFETY.md, DISCLAIMER.md, AUTHORIZED-USE.md, NETWORK-TESTING.md, FIRST-RUN-NOTICE.md) live alongside LICENSE. Settings live in ~/.gnulte.conf.

Safety rails

Parameter validation estimates impact before applying. The gateway and your own machine are refused as targets, and every run ends in a full cleanup.

Verification

Targets are verified reachable before shaping starts, and the spoof monitor revives dead arpspoof processes mid-test so runs complete.

Settings

GNULTE --settings is an interactive app: colour themes with live preview (classic, hacker, ocean, sunset, highcontrast, mono, custom), verbosity — easy, normal, expert — and console log modes.
