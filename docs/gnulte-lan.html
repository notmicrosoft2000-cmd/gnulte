gnulte-lan

The LAN watch — see who is online, how fast they’re moving, and who is misbehaving. Passive: frames are counted, nothing is shaped or intercepted.

▶ Watch a re-enactment in Studio

The watch

The whole network, live

Run it with no target and it auto-discovers the subnet — your own host and the router are skipped. It is a five-screen console: 1 hosts (the dashboard), 2 talkers (ranked, with bars and peers), 3 flows (per-pair conversations), 4 neighbours (the live ARP table) and 5 map (the Live Interconnection map — devices as nodes, live flows as pulsing edges). Rows shape themselves to your terminal — compact two-line blocks, the standard three-line block, or a four-line MORE variant with p50/p95 latency and session totals at 116+ columns — and the layout is stable per size, so the frame never “gets big and small” as values change. Every IP keeps one stable colour across every screen, so you can follow a device by hue alone.

Live rates

Down/up speed and packet rate per host, refreshed every second, with a running history — who is saturating the network is visible at a glance.

Health grades

Every host is graded: ✓ stable · ~ jittery (>30 ms or loss >2%) · ✗ loss ≥10% · ⚠ alarm. Defaults, or your own thresholds.

Five screens

1 hosts · 2 talkers (ranked ↓/↑ with bars and peers) · 3 flows (A ⇄ B pairs, root socket) · 4 neighbours (ARP) · 5 map (Live Interconnection — nodes + pulsing edges, root socket). Switch with the number keys, or t/f/n/m.

One colour per IP

Stable per-host hues across hosts, talkers, flows, ARP and the detail pane — red stays reserved for alarms, so finding a busy device by colour is instant.

Keys

Drive it from the keyboard

  • ↑ / ↓ — move between hosts, one row per press; repeat is your terminal’s own key-repeat, so holding no longer overshoots (v16 removed the app-side hold-repeat; two quick taps still queue as two moves)
  • ⏎ (or g) — hand the host off: opens gnulte -t <ip> against it in a fresh terminal, or prints the exact command when no terminal emulator is found
  • Tab / d — detail pane for the selected host (p50/p95, net share, flows)
  • 1–5 — switch screens: hosts · talkers · flows · neighbours · map (t/f/n/m too)
  • s — sort hosts · a — alarm-only view · x — save the watch to the shared device store
  • o — settings page · h — help · Esc — close pane / back to hosts (quit from hosts) · q — quit
  • On a wide terminal every row grows a fourth MORE line: session and peak averages, lifetime bytes, p50/p95 latency

Usage

Three ways to watch

# watch the whole LAN (auto-discovery) $ gnulte-lan # one host, up close $ gnulte-lan -t 192.168.1.20 # headless watch: 60s, CSV export, rate alarms $ gnulte-lan --duration 60 --export watch.csv --alarm-rate 500 # watch + share the results with gnulte / gnulte-scan (press x) $ gnulte-lan && # then x in the console → "live devices saved → …"

The watch is passive and needs no root to show latency, identity and alarms. Run it with the capture socket (sudo gnulte-lan — it auto-elevates) and screens 2–3, screen 5's map and the header gain byte-accurate talkers, per-pair flows, live net-edge map and net rates; without it they degrade to a polite ¡ speeds-free note and the FLOWS/MAP screens explain the root requirement instead of guessing. A live watch folds into the shared device store (~/.config/gnulte-go/devices.json) — with x or automatically when you quit — so gnulte and gnulte-scan see the same devices.

Options

Watching, tuned

FlagWhat it does
-t STRINGHost IP(s) to watch, comma-separated (empty = watch the whole LAN).
-i STRINGNetwork interface (default: auto-detect).
--interval NSeconds between updates (default from settings / 1).
--duration NAuto-stop after N seconds (0 = until Ctrl+C).
--history NRate / ping samples kept per host (settings / 60).
--alarm-rate NAlarm hosts above N kbps.
--alarm-latency-ms NAlarm hosts above N ms average ping.
--export FILEAppend per-tick samples as CSV to FILE.
--no-reportSkip the end-of-session HTML report.
-qQuiet: no banner, plain transcript for logs.
--versionPrint version and exit.

Every session ends with an HTML report (per-tool folder under ~/GNULTE Reports) unless you pass --no-report.
